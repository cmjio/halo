Halo v A language for AI workflows Built

Read. Plan. Replay.

Halo is a small language for pipelines of models and tools. Agents choose their own tool calls, inside policies the runtime checks before each one runs. You see everything a run could do before it starts, and can replay exactly what it did after.

Open the playground → Quickstart
01

The language

A pipeline reads top to bottom. Six operators cover the shapes AI workflows take; each stage's result flows to the next and stays in context.

OperatorNameWhat it does
|>CallAsk an agent, call a tool, or run another pipeline.
|?Gate · branchStop unless a condition holds, or take the first arm that matches.
|*Fan outRun calls side by side, or once for each item of a list.
|<>LoopSend an agent back with what the check found, until it passes.
|!Ask a personPause for an answer. Without a terminal, the run waits on disk.
~>ListenWait for an event from outside, such as a webhook.
02

Agents with tools

Give an agent tools and it works like an engineer. Every call it asks for is checked against its policies first.

AllowTools · AllowEffects
What it can see at all.
DenyArgs
Refuses calls whose arguments match.
ApproveTools
Asks a person first: terminal, link, or Slack. The run waits on disk.
Redact · Block
Screen tool results before the model reads them.

03

Plan, then replay

Before a run: every model call with its worst-case cost, every tool it could call and what that changes, and what needs approval. After: a recording that replays exactly, with no calls at all.

04
Tool packages
Any API can become a Halo tool. A halo-tool.json declares an HTTP API (no code runs), an MCP server, or a module. Every package is checked against its checksum when it loads; one that runs code needs --trust, kept on your machine, never read from the lockfile.

          
$ halo add stripe# then: tool Pay : Stripe()

Watches

              
Check a URL, file, or command on a schedule. A pipeline starts only when something changed, with what changed. No model call while nothing does.

              
{ "pipeline": "OnStatusChange",
  "url": "https://status.example.com/api.json",
  "every": "2m" }

            

            

              
Approvals in Slack

              
Paused runs are announced with Approve and Reject buttons. Each answers only the pause it was posted for; Slack's signature is checked on every click.

              
{ "slack": { "signingSecret": "Env.SLACK_SIGNING_SECRET" } }

            

            

              
Pipelines as MCP tools

              
Claude, Cursor, and other agents call your pipelines as tools, policies and spend limits still in force: at /mcp, or over stdio.

              
claude mcp add halo -- halo mcp ./pipelines
